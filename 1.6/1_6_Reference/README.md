# Еталон 1.6 — LDR + АЦП: формула vs `analogReadMilliVolts()`

Приклад «ідеально» зданої домашки в межах модуля 1: Arduino + `delay()`, без `millis()` і переривань. Перевірено: збирається в PlatformIO для ESP32-S3-DevKitC-1 без попереджень.

## Схема

```
3V3 ──[ LDR ]──┬──[ 10 кОм ]── GND
               │
             GPIO4   (ESP32-S3: ADC1_CH3)
```

- **Більше світла → менший опір LDR → вища напруга на GPIO4 → більший RAW.** Якщо поміняти LDR і резистор місцями, логіка інвертується.
- **Чому GPIO4.** На ESP32-S3 **ADC1 = GPIO 1–10** (працює завжди), **ADC2 = GPIO 11–20** (конфліктує з Wi-Fi). Для датчиків беремо ADC1. Теорія в інструкції (GPIO 32–39) описує класичний ESP32, а на S3 ці піни взагалі не АЦП.
- **Чому 10 кОм.** Опір LDR змінюється приблизно від 500 Ом (світло) до 50 кОм (темрява). 10 кОм — посередині (у логарифмічному сенсі), тому подільник дає помітну зміну напруги в кімнатному освітленні.

## Як запустити

```bash
pio run -t upload
pio device monitor
```

## Вивід

```
RAW=3273 noise=18 calc=2478 mV measured=2736 mV delta=-258 mV error=-9.43 %
```

Числа — ілюстрація на основі вимірів групи (RAW 3273 → 2736 мВ), а не запис з цього коду. `noise` = max − min RAW за серію з 16 вимірів, і його значення тут умовне.

## Що в коді і чому так

| Рішення | Навіщо |
|---|---|
| `constexpr` для піна, періоду, `ADC_MAX`, `U_REF_MV` | типобезпечно, видно в дебагері, жодних «магічних чисел» |
| `ADC_MAX = (1 << ADC_BITS) − 1` | бітність задана в одному місці, `4095` не треба переписувати руками |
| Явні `analogReadResolution(12)` і `analogSetPinAttenuation(PIN, ADC_11db)` | дефолти ядра можуть змінитися; явний рядок документує діапазон вимірювання |
| **Усереднення 16 вимірів** | один вимір «стрибає» на десятки одиниць коду; середнє відділяє шум від систематичної похибки |
| `analogRead` і `analogReadMilliVolts` **почергово** в одному циклі | це два окремі перетворення АЦП; так обидва середні відносяться до одного проміжку часу |
| Поле `noise` (max − min RAW) | одразу видно, що шум — десятки кодів, а розбіжність формули — сотні мВ: це різні явища |
| Формула в **цілих мВ**, множення в `uint32_t` **до** ділення | `RAW / 4095` у цілих = 0; `4095 × 3100` не влазить у `uint16_t`; float для цього не потрібен |
| `+ ADC_MAX / 2` перед діленням | округлення до найближчого, а не відкидання дробової частини |
| База похибки — **калібрована** напруга | вона еталон, а формула — те, що ми перевіряємо |
| Перевірка `measuredMv == 0` → `---` | у повній темряві замість `inf`/`nan` |
| Знак у Δ і % | видно напрям: формула **занижує** |
| `float`, не `double` | FPU ESP32-S3 лише одинарної точності, `double` рахується програмно |
| Кожен рядок самодостатній (`RAW=… calc=… measured=…`) | без шапки таблиці: рядок зрозумілий, навіть якщо монітор під'єднався пізніше |

## Головне питання: звідки ~10%?

Формула з умови вважає, що **один код АЦП = 3100 / 4095 ≈ 0,757 мВ** по всій шкалі. Виміри групи кажуть інше:

| RAW | `analogReadMilliVolts()`, мВ | мВ / код | Похибка формули |
|---|---|---|---|
| 765 | 668 | 0,873 | −13 % |
| 1907 | 1611 | 0,845 | −10 % |
| 3157 | 2639 | 0,836 | −9 % |
| 3866 | 3086 | 0,798 | −5 % |

Висновки, які має зробити студент:
1. **Похибка систематична:** формула завжди занижує. Від усереднення вона не зменшується, а шум — так.
2. **3,1 В — це рекомендований діапазон атенюації 11 дБ, а не напруга, що відповідає коду 4095.** Реальна крутизна посередині шкали ≈ 0,84 мВ/код.
3. **Характеристика АЦП нелінійна:** біля нуля похибка більша (зміщення нуля), біля верху менша (крива загинається до насичення).
4. **`analogReadMilliVolts()` точніший,** бо використовує заводські дані калібровки конкретного чипа, записані в eFuse, і апроксимацію кривої (curve fitting). Ідеальна лінійна формула цього не знає.

**Аналогія:** гумова лінійка, розтягнута нерівномірно. Якщо рахувати «одна поділка = один міліметр», помилка буде різна на різних ділянках, і повторні виміри її не виправлять. Калібровка — це таблиця, яка каже, наскільки розтягнута кожна ділянка.

## Що здати разом із кодом
1. **Схему або фото** подільника: видно, що зверху, що знизу і куди йде середня точка.
2. **Скрін або лог консолі** для 3–5 рівнів освітлення: долоня, кімната, лампа, ліхтарик.
3. **2–3 речення висновку:** яка похибка, чи вона систематична, чому формула з 3100 мВ розходиться з калібровкою.

## Пастки (Trust No Pin)
- **RAW завжди 4095:** середня точка закорочена на 3V3 або LDR під дуже яскравим світлом. Атенюація 11 дБ насичується раніше, ніж напруга на піні досягає 3,3 В.
- **RAW «плаває» без зміни світла сильніше, ніж зазвичай:** не вставлений 10 кОм, і пін висить у повітрі.
- **Шум RAW у десятки одиниць** — це нормально для АЦП ESP32. Довгі дроти й USB-живлення від ноутбука посилюють шум.
- **Пін з ADC2 (GPIO 11–20):** без Wi-Fi працює, з Wi-Fi — ні.

## 🚀 На виріст (поза програмою модуля)
- **Строгий період.** Зараз період дорівнює 100 мс плюс час вимірювання й друку. Неблокуючий варіант: `if (millis() - lastMs >= READ_PERIOD_MS) { lastMs += READ_PERIOD_MS; ... }`. Віднімання беззнакових чисел коректне і при переповненні `millis()`.
- **Один RAW → дві напруги.** У ESP-IDF є `adc_oneshot_read()` + `adc_cali_raw_to_voltage()`. Тоді формула і калібровка рахуються з **одного й того самого** коду, тож порівнюється сам метод, без шуму між вимірами.
- **Власна калібровка.** Двоточкова корекція (виміряти мультиметром дві напруги і знайти `k` та `b` у `U = k · RAW + b`) прибирає більшу частину систематичної похибки навіть без eFuse.
- **Апаратний фільтр.** Конденсатор 100 нФ від GPIO4 до GND (разом із 10 кОм це RC ≈ 1 мс) знижує шум до входу АЦП.
