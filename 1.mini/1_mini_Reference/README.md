# Еталон 1.mini - сутінковий вимикач (LDR + гістерезис + BC547B)

Приклад «ідеально» зданого мініпроєкту в межах модуля 1: Arduino + `delay()`, без `millis()` і переривань, процедурний код. Перевірено: збирається в PlatformIO для ESP32-S3-DevKitC-1 без попереджень.

## Схема

```
           +3V3                                   +5V
            |                                      |
          [LDR] R1                              [R4 270 Ом]
            |                                      |
            +------> GPIO4 (ADC1_CH3)            анод
            |                                    [LED]
        [R2 10 кОм]                              катод
            |                                      |
           GND                                     | колектор
                     GPIO5 --[R3 10 кОм]--- база  BC547B
                                                   | емітер
                                                  GND
```

| Вузол | Пін ESP32-S3 | Компоненти |
|---|---|---|
| Дільник LDR | GPIO 4 | R1 = LDR до 3V3, R2 = 10 кОм до GND |
| Ключ | GPIO 5 | R3 = 10 кОм → база BC547B, емітер → GND |
| Навантаження | - | +5V → R4 270 Ом → LED → колектор BC547B |
| Земля | GND | спільна для 3,3 В і 5 В частини |

Розпіновку BC547B (E-B-C) перевіряй за datasheet свого виробника: у корпусі TO-92 вона буває різна.

- Більше світла → менший опір LDR → вища напруга на GPIO 4 → більший код АЦП. Тому «темно» = код менший за поріг. Якщо поміняти LDR і R2 місцями, логіка інвертується.
- Чому GPIO 4. На ESP32-S3 ADC1 = GPIO 1-10 (працює завжди), ADC2 = GPIO 11-20 (конфліктує з Wi-Fi). Для датчиків беремо ADC1.
- Чому 5 В не шкодить піну. 5 В є тільки в колі колектора. GPIO 5 бачить лише R3 і перехід база-емітер (≈ 0,7 В), тож на пін ніколи не потрапляє більше 3,3 В.

## Розрахунки

### R4: струм світлодіода ~10 мА

```
R4 = (U_живл - Vf - Vce_sat) / I
   = (5,0 - 2,0 - 0,2) / 0,010 = 280 Ом  → найближчий з ряду E24: 270 Ом

I  = (5,0 - 2,0 - 0,2) / 270 ≈ 10,4 мА  ✓
P  = I² · R = 0,0104² · 270 ≈ 29 мВт   → резистор 0,125 Вт з запасом
```

Vf залежить від кольору, і R4 треба рахувати для свого світлодіода:

| Колір | Vf, В (типово) | R4 розрахунковий | E24 |
|---|---|---|---|
| червоний | 1,8-2,0 | 280-300 Ом | 270 / 300 Ом |
| жовтий / зелений (старий GaP) | 2,0-2,2 | 260-280 Ом | 270 Ом |
| синій / білий / яскраво-зелений (InGaN) | 2,8-3,2 | 160-200 Ом | 180 Ом |

Пін 5V на DevKitC живиться від USB, і під навантаженням там може бути ближче до 4,7-4,8 В. Для червоного LED це дасть ≈ 9,3 мА, тобто в межах «~10 мА».

### R3: чи насититься транзистор

```
Ib = (U_GPIO - Vbe) / R3 = (3,3 - 0,7) / 10 000 ≈ 0,26 мА
Потрібне β ≥ Ic / Ib = 10 / 0,26 ≈ 38
hFE BC547B = 200...450 (група «B», datasheet)  → β з запасом у 5-10 разів, транзистор у насиченні
```

Правило з практики: для надійного насичення беруть Ib ≈ Ic / 10...Ic / 20, тобто тут 0,5-1 мА. Наші 0,26 мА менші, але hFE групи B такий великий, що Vce_sat ≈ 0,1-0,2 В досягається. Якщо поставиш BC547A (hFE 110-220) або навантаження 50 мА - перерахуй.

Струм з GPIO 0,26 мА - мізерний, для піна ESP32-S3 безпечний.

### R2: чому 10 кОм у дільнику

```
U_GPIO = 3,3 · R2 / (R2 + R_LDR)
```

Опір фоторезистора змінюється від одиниць кОм на світлі до сотень кОм у темряві (наприклад, GL5528: 10-20 кОм при 10 лк, ≥ 1 МОм у темряві). R2 ≈ опору LDR при «пограничному» освітленні дає найбільшу зміну напруги саме там, де потрібно перемикатися: при R_LDR = 10 кОм на піні 1,65 В, середина шкали АЦП.

## Як обрати пороги

Пороги - не константи «з методички», а результат вимірювання у твоїй кімнаті:

1. Прошити еталон, відкрити Serial Plotter (115200).
2. Записати код АЦП у трьох станах: кімната зі світлом, долоня над LDR, вимкнене світло. Подивитися розмах шуму (як скачуть цифри в одному стані).
3. Пороги поставити між «темно» і «світло», а ширину мертвої зони (`THRESHOLD_LIGHT - THRESHOLD_DARK`) - у рази більшу за шум.

Приклад:

| Стан | Код АЦП | Шум |
|---|---|---|
| кімната | ≈ 2900 | ±10 |
| долоня | ≈ 700 | ±10 |
| пороги | `DARK = 1500`, `LIGHT = 2000` | зона 500 ≫ 20 |

Ці числа ілюстративні. Свої виміри треба записати в README своєї роботи.

## Як запустити

```bash
pio run -t upload
pio device monitor
```

Або Serial Plotter (Arduino IDE / розширення VS Code). Вивід:

```
adc:2893 dark:1500 light:2000 led:0
adc:1612 dark:1500 light:2000 led:0      ← між порогами: стан не змінився
adc:1384 dark:1500 light:2000 led:4095   ← нижче DARK: LED увімкнено
adc:1755 dark:1500 light:2000 led:4095   ← між порогами: LED і далі світить
adc:2104 dark:1500 light:2000 led:0      ← вище LIGHT: LED вимкнено
```

На графіку пороги - дві горизонтальні лінії, а `led` - сходинка. Саме тут видно гістерезис: на шляху вниз LED вмикається на нижній лінії, на шляху вгору вимикається на верхній.

## Що в коді і чому так

| Рішення | Навіщо |
|---|---|
| `constexpr uint8_t` / `uint16_t` для пінів і порогів | типобезпечно, видно в дебагері, тип під реальний діапазон (0...4095 влазить в `uint16_t`) |
| `static_assert(THRESHOLD_DARK < THRESHOLD_LIGHT)` | переплутані пороги - помилка компіляції, а не «вимикач, що клацає вночі» |
| Змінна стану `isLedOn` | без пам'яті про попередній стан гістерезис неможливий: між порогами рішення = «як було» |
| `decideLedState(adc, ledOnNow)` - окрема функція без доступу до пінів | логіку можна перевірити подумки чи тестом, не підключаючи плату |
| Запис у пін лише при зміні стану | пін не смикається зайвий раз, і є одне місце, куди додати «подію перемикання» |
| `pinMode` + `LOW` першим рядком `setup()` | навантаження в безпечному стані до першого вимірювання |
| Усереднення 16 вимірів, сума в `uint32_t`, округлення | один вимір АЦП шумить на десятки кодів; 16 × 4095 = 65 520 - впритул до межі `uint16_t` |
| Явні `analogReadResolution(12)` і `ADC_11db` | дефолти ядра можуть змінитися; явний рядок документує діапазон |
| Вивід `name:value` | одразу малюється в Serial Plotter, пороги видно як лінії |
| Процедурний код, жодного `new` / `String` | для такої задачі класи не потрібні; вся пам'ять статична |

## Що здати разом із кодом
1. Таблицю підключень або схему (текстом, як вище) з номіналами резисторів.
2. Розрахунок R4 для свого світлодіода (Vf, струм, номінал з ряду E24) і перевірку насичення транзистора.
3. Виміряні коди АЦП «світло / темно», шум і пояснення, чому обрано саме такі пороги.
4. Скрін Serial Monitor або Plotter, де видно перемикання в обидва боки.

## Пастки (Trust No Pin)
- LED не світить ніколи: переплутані виводи BC547B (E-B-C різняться у виробників) або LED вставлено навпаки.
- LED світить завжди: колектор і емітер переплутано, або R3 замкнуто прямо на 3V3.
- Код АЦП завжди 4095: середня точка дільника закорочена на 3V3. Завжди 0 - на GND або не вставлено LDR.
- Код «плаває» без зміни світла: не вставлений R2, і пін висить у повітрі.
- LED блимає на межі: пороги занадто близько (зона вужча за шум) або один поріг замість двох.
- LED коротко спалахує при ресеті: поки ESP32 перезавантажується, GPIO 5 на мить у високоімпедансному стані, і база транзистора «ловить» наводки. Рішення - резистор 100 кОм між базою і емітером: він тримає транзистор закритим, поки пін не налаштовано.
- «Реле замість LED»: голу котушку реле не можна вішати на GPIO. Тільки через транзистор і з діодом паралельно котушці (flyback): котушка при вимкненні дає викид напруги в десятки вольт.

## 🚀 На виріст (поза програмою модуля)
- Неблокуючий цикл: `delay(100)` замінити на `if (millis() - lastMs >= LOOP_PERIOD_MS) { lastMs += LOOP_PERIOD_MS; ... }`. Беззнакове віднімання коректне і при переповненні `millis()`.
- Фільтр у часі поверх гістерезису за рівнем: перемикати, лише якщо умова «темно» тримається, наприклад, 2 с. Тоді фари машини чи тінь від руки не перемкнуть світло.
- Апаратний фільтр: конденсатор 100 нФ від GPIO 4 до GND. Разом із дільником це RC-фільтр нижніх частот, який зменшує шум ще до АЦП.
- Калібрування в рантаймі: режим, у якому прошивка запам'ятовує мінімум і максимум АЦП і пропонує пороги, а не вимагає перепрошивки.
- ESP-IDF: `adc_oneshot_read()` + `adc_cali_raw_to_voltage()`, щоб працювати з напругою в мВ, а не з сирими кодами.
