# Практика 2.1 - пам'ять, volatile, atomic і кнопка BOOT

Живий код до лекції 2.1 «C++ для MCU: обмеження ресурсів та особливості». Жодної зовнішньої периферії: потрібна лише плата ESP32-S3-DevKitC-1 і USB-кабель. Кнопкою слугує BOOT (GPIO 0), вивід іде в Serial Monitor.

Одні й ті самі 6 кроків написані двічі:

| Папка | Фреймворк | Як обирається крок |
|---|---|---|
| `2_1_arduino/` | Arduino (`Arduino.h`, ядро 2.0.17 на ESP-IDF 4.4) | `build_src_filter` у `[env:stepN]` |
| `2_1_espidf/` | ESP-IDF 5.5 (`app_main`, драйвер `driver/gpio.h`) | макрос `PRACTICE_STEP` через `build_src_flags`, кожен файл обгорнуто в `#if PRACTICE_STEP == N` (ESP-IDF у PlatformIO не підтримує `build_src_filter`) |

Запуск (в обох проєктах однаково):

```bash
pio run -e step1 -t upload && pio device monitor
```

У VS Code: нижня панель PlatformIO → вибрати `env:stepN` → Upload and Monitor. Кожну підпапку відкривати окремим вікном VS Code.

## ⚠️ ESP-IDF і кирилиця в шляху

ESP-IDF не збирається, якщо в шляху до проєкту є кирилиця або пробіли (наприклад, `C:\Users\Олена\Документи\...`): падає kconfiglib на етапі конфігурації. Arduino-проєкт це не зачіпає. Клонуйте репозиторій у шлях латиницею без пробілів, наприклад `C:\esp\emb_28\`. Правило на весь курс: проєкти ESP-IDF - тільки в латинських шляхах без пробілів.

## Кнопка BOOT: що треба знати

- BOOT замикає GPIO 0 на GND. На платі вже є підтяжка 10 кОм до 3V3, тому в спокої пін = 1, натиснута = 0. Внутрішню pull-up у коді вмикаємо про запас.
- GPIO 0 - strapping-пін. Якщо тримати BOOT у момент ресету чи подачі живлення, чип стартує в режимі завантажувача, і програма не запуститься. Натискати BOOT лише після старту.
- Брязкіт контактів кнопки BOOT такий самий, як у будь-якої тактової кнопки: див. крок 3.

### Крок 2: доказ з дизасемблера

Компілятор справді викидає перевірку. Ось `loop()` з `USE_VOLATILE = false` (Arduino, `-Os`):

```
420017eb:  l32r   a8, ...        ; адреса plainFlag
420017ee:  l8ui   a9, a8, 0      ; прочитати plainFlag ОДИН раз
420017f1:  bnez.n a9, 420017f8   ; якщо вже true - вийти
420017f3:  j      420017f3       ; інакше - стрибок сам на себе, назавжди
```

Подивитися самостійно:

```bash
~/.platformio/packages/toolchain-xtensa-esp32s3/bin/xtensa-esp32s3-elf-objdump -d -C .pio/build/step2/firmware.elf | less
```

і знайти `<loop()>` (Arduino) або `<app_main>` (ESP-IDF). З `USE_VOLATILE = true` усередині циклу з'являється `memw` + `l8ui`: читання з пам'яті на кожному оберті:

```
420017ee:  memw                  ; бар'єр пам'яті
420017f1:  l8ui   a8, a9, 0      ; прочитати volatileFlag
420017f7:  beqz   a8, 420017ee   ; ще false - на початок, читати знову
```

В ESP-IDF objdump інколи «збивається» на літералах усередині `app_main` і показує сміття на кшталт `ee.vmulas...`. Тоді дизасемблюй з конкретної адреси: `objdump -d --start-address=0x... --stop-address=0x... firmware.elf`.

### Крок 2 і оптимізація: баг, що ховається в debug-збірці

ESP-IDF за замовчуванням збирає з `-Og` (Debug). З ним компілятор перечитує `plainFlag` на кожному оберті, і крок 2 без `volatile` «працює». Тому в `2_1_espidf/sdkconfig.defaults` увімкнено `CONFIG_COMPILER_OPTIMIZATION_SIZE=y` (`-Os`, як в Arduino), і тільки тоді цикл зависає. Перевірено дизасемблером в обох варіантах.

Для студентів це окремий урок: «працює в Debug, падає в Release» - класичний симптом пропущеного `volatile` (або гонки). Відсутність бага в одній збірці нічого не доводить.

### Крок 4 і 5: чому саме два ядра

На одному ядрі без RTOS гонка між ISR і `loop()` теж буває, але рідко, і на уроці її не впіймати. ESP32-S3 має два ядра, і коли дві задачі працюють на різних ядрах справді одночасно, гонка проявляється тисячі разів за секунду. Це найнаочніший доказ тези лекції «volatile не гарантує атомарності».

Аналогія для кроку 4: два касири ведуть один зошит із виторгом. Кожен читає число, додає в голові свою суму і записує. Якщо обидва прочитали «100» одночасно, обидва запишуть своє «100 + x», і одна покупка зникне. `volatile` лише гарантує, що касир щоразу дивиться в зошит, а не пам'ятає число. Атомарна операція - це «тільки один олівець на двох».

Аналогія для кроку 5: годинник з окремими цифрами годин і хвилин, і ти глянув на нього о 12:59:59. Години прочитав «12», а поки переводив погляд, хвилини стали «00». Вийшло 12:00, хоча такого часу не було.

### Крок 6: «вікно» в шаблоні з лекції

Шаблон з розділу 3.2 лекції:

```cpp
if (button_pressed) {
  button_pressed = false;
  // ...
}
```

правильно показує навіщо `volatile`, але має гонку: між читанням і скиданням може прийти ще одне переривання. У прикладі з лекції скидання стоїть одразу після перевірки, тож вікно маленьке. Але студенти часто ставлять його в кінці обробки, і тоді вікно - уся обробка. `exchange(false)` прибирає вікно повністю: «забрати подію і скинути прапор» стає однією неподільною операцією.

## Різниця Arduino і ESP-IDF

| | Arduino | ESP-IDF |
|---|---|---|
| Точка входу | `setup()` / `loop()` у задачі loopTask на ядрі 1 | `app_main()` у задачі main на ядрі 0 |
| ISR | `attachInterrupt(pin, fn, FALLING)`, `void fn()` | `gpio_install_isr_service()` + `gpio_isr_handler_add()`, `void fn(void*)` |
| Налаштування піна | `pinMode()` | `gpio_config_t` однією структурою |
| Затримка | `delay(ms)` | `vTaskDelay(pdMS_TO_TICKS(ms))`; у `sdkconfig.defaults` тік 1000 Гц, як в Arduino |
| Оптимізація | `-Os` | за замовчуванням `-Og`; у `sdkconfig.defaults` увімкнено `-Os`, інакше крок 2 не зависне |
| Busy-wait у кроці 2 | тихо висить (Arduino не стежить за IDLE на ядрі 1) | Task Watchdog раз на 5 с скаржиться на голодну задачу IDLE0 |
| C++ | gnu++11 | gnu++2b (C++23), тому `++` для `volatile` дав би попередження про застарілість |
| 64-бітний `is_lock_free()` | не лінкується (немає `__atomic_is_lock_free`), тому в коді макроси `ATOMIC_*_LOCK_FREE` | так само, для однаковості |

## Що навмисно не включено (це домашнє завдання 2.1)

- Неблокуюче блимання з `enum class LEDState` і `millis()`.
- Config-клас зі `static constexpr`.
- Вимірювання часу суперциклу на 100 000 ітерацій.
- Циклічна зміна режимів BLINKING → ON → OFF кнопкою з ISR.

Практика показує механізми (де лежать дані, `volatile`, атомарність, подія з ISR), а не готові частини домашки. Світлодіод і зовнішні кнопки не використовуються зовсім.
