# Еталон 1.4 — Два світлодіоди, зовнішня кнопка та BOOT

Приклад «ідеально» зданої домашки в межах модуля 1: Arduino + `delay()` + `digitalRead()`, без `millis()` і переривань. Перевірено: збирається в PlatformIO для ESP32-S3-DevKitC-1.

## Схема

```
GPIO15 ── 220 Ом ──▶|── GND     LED 1
GPIO16 ── 220 Ом ──▶|── GND     LED 2
GPIO21 ──[кнопка]── GND         зовнішня кнопка, INPUT_PULLUP
GPIO0  ── кнопка BOOT на платі  (зовнішня підтяжка вже є)
```

### Тактова кнопка має 4 ніжки — як не помилитися
Ніжки кнопки всередині попарно з'єднані: дві пари, а кнопка замикає пару з парою. Якщо підключитися до двох ніжок **однієї пари**, отримаєш «кнопка натиснута завжди». Якщо пари не ті й макетка ще й закорочує ряд, отримаєш «ніколи не натискається».
**Правило без пам'ятання розпіновки: підключай по діагоналі.** Протилежні по діагоналі ніжки завжди належать різним парам. Сумніваєшся — перевір мультиметром у режимі продзвонки.

## Головна пастка завдання: `delay(1000)` «глухий»

Наївне рішення:
```cpp
void loop() {
  if (digitalRead(BTN_EXT) == LOW) mode = 1;
  if (digitalRead(BOOT)    == LOW) mode = 2;
  if (mode == 2) { led1 on; delay(1000); led2 on; delay(1000); }  // 2 секунди «глухоти»
  ...
}
```
Кнопки читаються раз на цикл. У режимі 2 цикл триває 2 с, тож коротке натискання майже завжди «губиться», і користувач мусить **тримати** кнопку. Перевіряючи домашку, обов'язково натисни кнопку коротко посеред паузи.

**Рішення в межах модуля 1 — `waitMs()`:** той самий `delay`, але по 1 мс у циклі з опитуванням кнопок. Реакція стає миттєвою, а з інструментів використано лише `delay()` і `digitalRead()`.

## Чому тут не потрібен debounce
Кнопка **встановлює** конкретний режим, а не **перемикає** його. Брязкіт дає 5–10 «натискань» за кілька мс, і кожне з них встановлює той самий режим, тож результат не змінюється (ідемпотентність). Якби одна кнопка перемикала 1 → 2 → 1, брязкіт давав би випадковий результат, і без debounce не обійтися (урок 1.5).

## Інші деталі, на які варто звернути увагу
- **GPIO 0 — strapping-пін.** Якщо BOOT затиснута під час ресету, ESP32-S3 увійде в режим прошивки. Для BOOT це нормально, але **не вішай на GPIO 0 / 3 / 45 / 46 зовнішню схему, яка може тягнути пін при старті**.
- **Лог у Serial при зміні режиму.** Без нього важко зрозуміти, чи режим не перемкнувся, чи LED неправильно підключені.
- **Обидві кнопки одночасно** — пріоритет у зовнішньої (режим 1). Рішення свідоме й описане в коді.

## Що здати разом із кодом
1. Схему або фото макета (видно резистори 220 Ом і підключення кнопки).
2. Відео: перемикання обох режимів **коротким** натисканням.

## 🚀 На виріст (поза програмою модуля)
`waitMs()` — це перехідний варіант. «Промислове» рішення — неблокуючий цикл на `millis()` (`if (millis() - stepStart >= periodMs)`), де `loop()` прокручується тисячі разів на секунду і нічого не чекає. Порівняння через **віднімання** беззнакових чисел коректно працює навіть при переповненні `millis()` (~49,7 доби).
